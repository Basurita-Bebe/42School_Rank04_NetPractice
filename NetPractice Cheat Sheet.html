The block method

Use it to find the network an IP belongs to.

  1. Find the mask octet that isn't 255 (or 0 after 255s).
  2. Block size = 256 − that value.
  3. Count in multiples of the block size: 0, size, 2×size… The largest multiple ≤ the IP's octet is the network.
  4. Broadcast = next multiple − 1.
  5. Usable = network + 1 … broadcast − 1.
10.0.0.90 /28 (255.255.255.240) block = 256 − 240 = 16 0 16 32 48 64 [80] 96 … 80 ≤ 90 < 96 network 10.0.0.80 usable 10.0.0.81 – 10.0.0.94 broadcast 10.0.0.95 route destination → 10.0.0.80/28

Rules that make a level pass

These are the things that most often break a level.

  • Same network = same mask + same blockDevices on one switch or one cable need matching masks and IPs in the same block.
  • Never assign network or broadcastThe first and last address of a block are reserved.
  • A switch has no IPIt only joins devices that are already on one network.
  • Each router interface is its own networkIts IP and mask must match the devices on its side.
  • Gateway = nearest router interface on your sideIt must be in your own block. Written as a route: default → gateway IP.
  • Route = network/mask → next hopThe destination is a network address (10.0.0.64/26), never a host IP. The next hop is a router interface on a network you share.
  • Traffic goes both waysEvery route has to have a return route.
  • No overlapping networksTwo different networks can't share addresses (e.g. /24 and a /26 inside it on different links).

Level checklist

Go through this in order when a goal says KO.

  • Read the goals: who must reach whom?
  • Note which fields are locked. They decide what the other side must be.
  • Every IP valid (4 octets, 0–255, not 127, not network/broadcast)?
  • Every mask valid (only 1s then 0s)?
  • Each link / switch: same mask and same block on every device?
  • Each host: default → its router's interface?
  • Each router: a route to every remote network, next hop on a shared link?
  • Return path configured too, including the Internet's route back?
  • Read the logs at the bottom, then press Check again.
  • Solved? Click Get my config before moving on.

Level guide: what each level tests

The defense gives you random numbers, so this lists the pattern and method for each level rather than the values. Always start from the locked (shaded) fields.

1
Two separate pairsValid IP · same network
Setup
Two hosts per cable, no router. One IP editable in each pair.
Method
Look at the locked mask to see which octets are the network part. Copy those octets from the locked IP. Pick a free host number.
Traps
Octets above 255. A network octet that differs (e.g. 104.93 vs 104.97 with /24).
2
Masks and tiny blocksMask validity · /27 · /30 · 127
Setup
Two pairs again, now with split-octet masks.
Method
Fix invalid mask values first (only 0,128,192,224,240,248,252,254,255). Use the block method to find the locked IP's block, then put the other host in it.
Traps
127.x is loopback, so never use it. With /30 there are only 2 usable addresses per block. Avoid network and broadcast addresses.
3
Several hosts on one switchOne network, one mask
Setup
Three hosts on a switch. Usually one mask or IP is locked.
Method
Everyone on a switch gets the same mask as the locked one, and IPs in the same block, all different.
Traps
A block too small for the number of hosts. A switch has no IP.
4
Router on a switchInterfaces must not overlap
Setup
A router with 3 interfaces. One faces a switch with 2 hosts.
Method
Map the locked interfaces on a 0–255 ruler. The switch network must fit in the free gap. Choose the mask whose block fits that gap exactly.
Traps
A duplicate IP with another interface. A mask so big it overlaps another interface's network (it may still pass, but it's wrong).
5
First routesGateway · default route
Setup
Two hosts on different router interfaces. Host routes are editable.
Method
Each host's IP and mask match its router interface. Route: default → router interface on its own side.
Traps
A mask split in the 3rd octet (e.g. /18): same block method, one octet left. Typos like 10..0.0.0.
6
The InternetRouter default · return route
Setup
Host → switch → router → Internet.
Method
Host: 0.0.0.0/0 → R1. Router: 0.0.0.0/0 → Internet next hop. Internet: host network/mask → router.
Traps
A switch is never a gateway. Internet destination = a network address, not the host's IP.
7
Subnet one range, two routersDesign · /30 links
Setup
A → R1 → R2 → C, all in the same /24. Nearly everything is editable.
Method
One small block per cable (/30), starting from the locked IPs. Hosts: default → gateway. Each router: remote network/mask → neighbour's IP on the shared cable.
Traps
"Correct IP reached but wrong host" means duplicate or overlapping networks. A route to a cable the router is already on is useless.
8
Carving a locked rangeAggregation
Setup
Two routers, two hosts, the Internet. The Internet's return route destination is locked.
Method
That locked route is the whole space for all inside networks. Place the host networks side by side so one route on R1 covers both (e.g. two /28s → one /27).
Traps
A locked next hop tells you an interface's IP (e.g. R2 → .62 means R13 = .62).
9
Private IP trapPublic addressing · hidden typos
Setup
Two routers, 4 hosts, the Internet, 6 goals.
Method
Any host that talks to the Internet must be on a public network. Redesign 10.x / 192.168.x networks, then do the routes as in level 7.
Traps
"invalid route" when everything looks right means a trailing space, so retype the field. D's locked gateway reveals R23's IP.
10
Everything togetherMasks too big · one Internet route
Setup
Two routers, switch, 4 hosts, Internet, 7 goals. Most IPs locked, many masks editable.
Method
Map every locked network on the 0–255 ruler. Fit the unlocked network into the free gap. Every mask must match its neighbour. The Internet needs one route covering all inside networks.
Traps
"multiple interface match" or a router sending straight onto the wrong cable means a mask that's too big. Don't write / in front of a dotted mask.

Reading the logs

Find the last line before a path stops. It names the device and the problem.

Log lineUsually means
destination IP reachedThis direction works
packet not for me / loop detectedNormal: a switch copies packets to every cable
invalid IP addressTypo, octet > 255, network/broadcast address, or bad mask
invalid routeDestination isn't a valid network (host IP, typo, hidden space)
destination does not match any routeRoute missing, or it doesn't cover that address
no interface for gateway XGateway X isn't on any network this device is plugged into
multiple interface matchTwo interfaces' networks overlap: a mask is too big
Correct IP reached but wrong hostDuplicate IP / overlapping networks
No reverse wayReturn route missing (often the Internet's)
